작성·공식 가격 확인일: 2026-09-08 UTC.
실행 상태·진행도·작업 이력의 원본은 [프로젝트 현황](project-status.md)이다.

## 확정 사항과 판단이 필요한 사항

| 항목 | 현재 합의 / 제안 | 판단 기준 |
| --- | --- | --- |
| 제품 목표 | Flutter Android 테니스 코칭, 향후 움직임·체형을 반영한 3D 결과 | 기존 목표 유지. 사용자 승인 전 2D 전용 제품으로 변경하지 않음 |
| 기반 기술 | FastAPI, PostgreSQL, Riverpod, 계층 분리 | 기존 구현과 공개 API를 재사용하고 공급자 연동을 서비스 어댑터로 격리 |

| 진행 기록 | 사용자가 새 업무·진행·완료를 Markdown에 계속 기록하도록 요청 | `AGENTS.md` 규칙과 `project-status.md`를 매 작업 갱신 |
| 초기 분석 범위 | 2D 포즈 → 지표 → 3D 확대는 AI의 추천, 미승인 | 첫 대상 동작·촬영 조건·출력·정확도·대기시간을 T-02에서 결정 |

| 영상·가중치 저장 | R2 또는 S3 후보 | API·GPU 간 전송량, 위치, 비공개 접근, 삭제·백업 정책 |
| 학습·추론 GPU | RunPod Pod 학습, RunPod Serverless/Modal 추론 후보 | 먼저 모델을 실행해 메모리·속도·비용 확인. 브랜드를 먼저 고정하지 않음 |
| 예산·계정·리전 | 미정 | 개발/스테이징/운영별 예산, 데이터 위치, 사용자 규모를 T-06에서 확정 |

GPU 필요성은 작업에 따라 다르다. FFprobe 검사와 일부 가벼운 포즈 추론은 CPU로 가능하며,
본격적인 딥러닝 학습·고비용 영상/3D 추론은 GPU 사용을 검토한다. 특정 GPU의 VRAM만 보고
모델이 실행 가능하거나 충분히 빠르다고 보장하지 않는다. 모델·해상도·배치별 벤치마크가 필요하다.

MediaPipe, YOLO Pose, MMPose는 앞 대화에서 거론된 탐색 후보명이며 채택 목록이 아니다.
T-04에서 공식 문서·모델/가중치/학습 데이터 라이선스·상업적 이용 조건을 확인하고 비교한다.
처음부터 새 모델을 학습하기 전에 사전학습 모델의 기준선을 측정하고, 부족할 때만 T-11을 진행한다.
사용자 영상 업로드 동의와 모델 학습에 재사용하는 동의를 같은 것으로 취급하지 않는다.

## 환경을 바꿀 때의 변경 범위

| 영역 | 재사용할 부분 | 추가하거나 검증할 부분 |
| --- | --- | --- |
| Flutter | 기존 화면·Riverpod·repository | 운영 API 원점, 실제 AI 결과 계약·화면, release 서명 |
| FastAPI | 인증·영상 API, 서비스, repository | 클라우드 비밀 주입, health, AI 서비스 어댑터 |
| PostgreSQL | ORM 모델·Alembic 이력 | TLS/인증서 검증, 연결 수, 풀 호환성, 외부 복원 |
| 영상 저장 | 로컬/S3 저장소 인터페이스와 구현 | 실제 제공자 multipart/Range/삭제, 결과 용량, 전송비 |
| worker | PostgreSQL 작업 claim·lease·재시도·취소·정리 | GPU 작업 제출·조회/완료통지·중복 방지·실행시간·복구 |
| 배포 | 기존 Dockerfile, FFmpeg, 비루트 실행 | 내부 DB를 전제한 Compose와 별도 운영 설정, migration 순서 |

환경변수 변경으로 재사용하는 방향이지만, 현재 Compose는 `POSTGRES_HOST=postgres`로
덮어쓴다. DB TLS는 API/worker뿐 아니라 Alembic에도 적용해야 한다. `DATABASE_URL`은
현재 설정 API에 없으므로 공급자의 예제를 그대로 복사하지 않는다.

외부 DB는 백업을 새 빈 대상에 복원하는 연습부터 한다. 기존 스키마를 덤프에서 복원하는 경우
먼저 같은 테이블을 마이그레이션으로 만들지 않는다. 복원 후 Alembic 리비전을 확인하고
필요한 후속 마이그레이션만 적용한다. DB와 영상은 함께 정합성을 검증한다.

## 일반 클라우드 장단점과 비용

USD/월, 단일 환경의 참고 계산이다. 세금·환율·개발 인건비는 제외하며 용량 보장은 아니다.
기본 비교는 API·worker 각 1개, 관리형 DB 1개이며 GPU와 영상 저장·요청·전송은 별도다.

| 선택지 | 기본 비용 예시 | 장점 | 단점·추가 확인 |
| --- | --- | --- | --- |
| Render API·worker·PostgreSQL | `$7 + $7 + $19 = $33` | 배포·일반 서버·DB를 한곳에서 관리 | API/worker 각각 512MB RAM. 영상 처리 부하와 전송비, DB 추가 디스크, workspace 비용 확인 |
| Render + Neon Launch DB | 아래 상시 가정에서 약 `$33.70` | 사용량 기반 DB, 유휴 중지 활용 가능 | 현재 worker의 상시 DB 조회로 유휴 절감이 제한됨; 공급자 간 네트워크·복구 이력 별도 |
| Render + Supabase Pro DB | `$7 + $7 + $25 = $39` | 첫 Micro 프로젝트와 DB 8GB, 일일 백업 7일 포함 | 추가 프로젝트/compute 비용. 기존 인증을 Supabase Auth로 바꿀 필요는 없음 |
| Render에서 worker 2GB로 증설 | `$7 + $25 + $19 = $51` | worker RAM 여유 | GPU 포함 아님. 2GB도 실제 모델·동시 처리 수를 측정해야 함 |
| AWS / GCP | 리전·서비스·인스턴스 확정 후 계산 | DB·컴퓨팅·네트워크를 통합 설계 가능 | 구성·운영 부담; 디스크·로드밸런서·NAT·전송·백업 등에 따라 큰 차이 |

근거: [Render 요금](https://render.com/pricing), [Neon 요금](https://neon.com/pricing),
[Supabase 요금](https://supabase.com/pricing). AWS/GCP는
[RDS PostgreSQL 요금](https://aws.amazon.com/rds/postgresql/pricing/)과
[Google Cloud GPU 요금](https://cloud.google.com/products/compute/gpus-pricing)을 바탕으로
선택한 리전의 전체 구성을 산정한다. 이전 대화의 AWS/GCP `$70~150+`는 구성 없는 추정으로 보류한다.

Neon Launch의 `$15/월`은 간헐 부하·1GB DB의 예시이지 고정요금이 아니다. 현재 worker는
기본 2초마다 DB를 조회하므로 유휴 중지를 기대하기 어렵다는 것이 코드 기반 판단이다.
0.25 CU가 월 730시간 활성이고 DB가 1GB라고 **가정**하면 DB 비용은
`0.25 × 730 × $0.106 + 1 × $0.35 = $19.695`, API·worker를 더하면 약 `$33.70`이다.
복구 이력 저장·네트워크·더 큰 CU 사용은 별도다. 이 가정의 182.5 CU-hours는 Free의
월 100 CU-hours를 초과한다. 무료 DB/API를 상시 운영 예산의 확정 전제로 삼지 않는다.

DB만 이전해도 API가 Codespace에 남아 있으면 Codespace 중지 시 앱 서버는 멈춘다.
상시 모바일 이용에는 API·worker·DB·영상 저장소를 모두 외부 운영 환경에 배치해야 한다.

## 학습과 운영 추론 환경

학습은 개발자가 모델을 개선하는 작업이고, 추론은 학습된 모델로 사용자 영상을 분석하는 작업이다.
일반 API·DB 서버와 GPU 실행을 분리하고 영상·가중치·결과는 외부 저장소에서 버전별로 관리한다.

| 환경 | 적합한 단계 | 장점 | 단점·검증할 점 |
| --- | --- | --- | --- |
| RunPod Pod | 대화형 모델 실험·지속적인 학습 | GPU/컨테이너 선택, 시간 기반 대여 | 인스턴스 종료·checkpoint·디스크 관리 필요. 멈춘 뒤 보존 디스크 과금 확인 |
| RunPod Serverless | 간헐적인 사용자 추론 | Flex worker를 0개로 축소 가능 | cold start, 모델 로딩·idle 비용, 가용 GPU, timeout·재시도 설계 |
| Modal | Python 기반 배치·사용자 추론 | 자동 확장과 Python 배포 편의 | 공급자 SDK 어댑터 필요. CPU·RAM·스토리지 별도 과금, 지역 옵션 확인 |
| GCP GPU / Vertex AI | 같은 클라우드에서 학습·운영 관리 | 리전·데이터·ML 운영 통합 선택지 | GPU quota·가용성·VM 전체 가격과 저장·전송 비용 확인 |
| AWS GPU / SageMaker | 조직적인 학습·배포·모니터링 | 다양한 관리형 ML 기능 | 초기 설정·권한·비용 복잡도. 선택한 추론 상품의 GPU 지원을 별도 확인 |

아래 표는 확인한 단가 예시다. 가장 싼 GPU가 영상당 비용도 가장 싼지는 벤치마크로 판단한다.

| 상품 | 단가 예시 | 단순 계산 예시 |
| --- | --- | --- |

향후 연동 흐름은 `영상 저장 → 기존 DB 작업 → CPU worker의 GPU 제출 → GPU 처리 → 결과 저장 →
worker의 상태 반영 → 앱 조회`다. 현재 없는 GPU 제출·상태조회/완료통지를 T-10에서 구현한다.
GPU 공급자에 운영 DB 비밀번호를 배포하지 않고, 제한된 입력/출력 접근과 인증된 작업 연동을 설계한다.
기존 성공 상태값 `succeeded`를 유지하며 모델 로딩은 매 요청이 아닌 GPU worker 수명에 맞춘다.

## 비용을 판단할 수 있는 계산 예시

아직 모델 속도를 측정하지 않았으므로 아래는 총액 예측이 아닌 **명시된 항목의 소계**다.

| 시나리오 | 가정 | 소계 |
| --- | --- | ---: |
| 일반 서비스 1개 환경 | Render API $7 + worker $7 + DB $19 | `$33/월` |
| 위 구성 + 월 1,000건 추론 | 건당 L4 과금 GPU 시간 120초, GPU만 `1,000 × 120 × 0.000222` | `$59.64/월` |
| 위 구성 + 모델 실험 | 추가 A5000 Pod 50시간 `50 × 0.27` | `$73.14/월` |

추가 계산 항목: 영상·모델·checkpoint·DB 저장, 객체 요청, API 전송, GPU와 함께 쓰는 CPU/RAM,
추가 모델 준비·대기·재시도 시간, 별도 스테이징, 도메인, 유료 workspace, 세금·환율, 개발 인건비.
120초는 측정값이 아니다. 현재 worker 전체 처리 제한 90초와도 맞지 않으므로 구현 가능성이나
서비스 지연시간의 약속으로 사용하지 않는다.

이전 대화의 개발 비용 `$29~68+` 합계에는 같은 표의 학습비가 포함되지 않았다.
또한 “월 1,000건이면 $52~80”은 저장·전송량과 실측 추론시간이 없는 추정이었다.
다음 예산 판단에는 이 문서의 단가·산식·제외 항목을 사용하고 모델 측정 후 갱신한다.
